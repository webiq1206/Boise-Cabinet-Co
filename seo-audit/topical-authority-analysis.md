# Topical Authority Analysis - Boise Cabinet Co

Content is **topic-hub driven** (`shared/contentHubs.ts`): 8 hubs, each = 1 pillar guide + N blog clusters + a `/blog/category/[hub]` page. The disconnect: clusters attach to topic hubs, but the customer-facing service pages are the 13 **rooms** - which are NOT the center of their cluster (a room links to just 1 pillar guide + products).

| Finishes (299) & Doors (6) as a topic | 2 guides only | detail pages isolated | **Thin & orphaned** |
| Location (8 cities) | none | 8 guides + footer | Good geo, no service x city depth |

## Roadmap to category leadership
1. **Wire the manifest into catalog templates** (biggest lever, lowest effort) - see internal-linking-plan.
2. **Make rooms true hubs** - blog cluster + finishes/doors + projects + sibling rooms per room.
3. **Register finishes/doors** into the linking system so the topic stops being orphaned.
4. **Build out bathroom-vanities** to ~8 clusters (small/double/floating/materials/ADA).
5. **Add service x location depth** - room x city links or lightweight city landing sections.
6. **Expand blog depth** (Phase 3) so the strong cluster *count* is matched by cluster *quality*.

**Bottom line:** the content **breadth** is strong (the clusters exist); the gaps are **wiring** (catalog templates render no related links; rooms aren't hubs) and **depth** (thin blog posts, thin bathroom cluster).
